# Minimal (Tiendu theme)

A minimal, high-contrast storefront theme for the Tiendu Theme Framework
(engine 2): oversized type, lots of room, black and white plus the store's
color. Plain Liquid, GraphQL data files, CSS and JavaScript. No build step.

It is the Theme Framework version of the `headless-minimal` SvelteKit template
and looks and behaves the same.

The desktop header and the bottom of the mobile menu open Tiendu's account
and wishlist overlays. Product cards and
product pages have save buttons; signing in can finish saving the selected
product, and all hearts follow the shopper's current favorites.

- `CHECKLIST.md`: steps to turn the theme into a real store.
- `DESIGN.md`: design rules, tokens and image art direction.
- `AGENTS.md`: guide for AI agents working on the theme.

## Work on it

A store's theme is a Git repository hosted by Tiendu. Every branch is a
preview; pushing to `live` publishes.

```bash
git clone http://localhost:4500/<storeHandle>.git
cd <storeHandle>
git switch -c my-change
# edit, commit
git push -u origin my-change   # prints the preview URL
```

The password is a store API key (Merchant Center → Ajustes → Tienda →
Desarrollo y API → Claves de API). Keep it in a Git credential helper, never
in the remote URL. Every checked push ends with a `remote: checks:` line;
without it the checks didn't run. See the Theme Framework docs for publishing
and undoing a release, and `CHECKLIST.md` for publishing this theme the first
time.

## CSS organization

`assets/theme.css` holds design tokens, resets, typography and base utilities.
Component styles live in `assets/css/`; each file includes its responsive rules
and interaction states:

| File | Owns |
| --- | --- |
| `controls.css` | Buttons, inputs, chips, breadcrumbs, shopper controls, ratings and dialogs. |
| `layout.css` | Header, mobile menu, newsletter, footer and WhatsApp button. |
| `home.css` | Section headers, hero, split content, collection links and benefits. |
| `catalog.css` | Listing/search headers, product cards/grid, sorting, pagination and empty states. |
| `product.css` | Product detail, options, quantity, gallery, sharing, accordions and reviews. |
| `content.css` | Merchant rich text and content image blocks shared by pages and articles. |
| `pages.css` | Static-page layout. |
| `blog.css` | Blog previews/cards, list and article layout. |

The root layout loads `theme.css`, followed by its ordered `css_modules` list,
using `asset_url | stylesheet_tag` for every file. Direct stylesheet links retain
theme versioning and let the browser fetch files in parallel. There is no CSS
`@import` chain or build step. The same ordered set loads on all routes because
components such as product cards, blog previews and dialogs are shared. Preserve
the cascade order and edit the component's own file when adding styles.

## JavaScript organization

`assets/theme.js` is a small initialization entry point. Behavior lives in native
ES modules under `assets/js/`:

| Module | Responsibility |
| --- | --- |
| `client.js` | One shared Store SDK client; configure initialization options here. |
| `cart.js` | Cart badge, refreshes and checkout. |
| `shopper.js` | Account, wishlist state and delegated save actions. |
| `menu.js` | Mobile menu, Escape/backdrop and animated closure. |
| `forms.js` | Search overlay/fallback and newsletter submission. |
| `catalog.js` | Sorting and automatic pagination, including wishlist updates on appended cards. |
| `product.js` | Variant selection, price/stock, quantity, add to cart, sharing and analytics. |
| `gallery.js` | Product gallery arrows, thumbnails and keyboard navigation. |

The inline import map in `routes/+layout.liquid` maps `@minimal/<name>` and
`@tiendu/sdk` to URLs generated by `asset_url`. It appears before `tiendu_head`
and all module scripts. Module preloads fetch known dependencies in parallel;
every URL carries the same theme version, and the released SDK is unchanged.

Import features directly, for example:

```js
import { refreshCart } from '@minimal/cart'
```

When adding a module, register its name in the layout's `js_modules` list and
initialize it from `assets/theme.js`. That list generates both the map and preload
URLs. Keep each feature's `data-*` guards, use the shared client and avoid import
cycles. No build step or external import-map request is needed.

## Routes

- `/` home (sections listed in `routes/+page.liquid`)
- `/productos/[handle]` product with variant picker and add to cart
- `/categorias/[handle]` collection with subcategories, sort and "load more".
  All products is the virtual collection `todas`, at `/categorias/todas`.
- `/busqueda?q=…` search results (the header search opens Tiendu's search overlay)
- `/blog`, `/blog/[handle]` blog list and post
- `/paginas/[handle]` static pages (policies)
- 404: `routes/+error.liquid`. Tiendu serves `/sitemap.xml` and `/robots.txt`.
